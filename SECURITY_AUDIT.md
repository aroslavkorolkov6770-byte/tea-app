# Аудит безопасности Ватэс

Дата проверки: 30 июля 2026 года.

## Область проверки

Проверены:

- авторизация, регистрация, сессии и смена пароля;
- административные маршруты управления сотрудниками;
- общий API хранения, разграничение доступа к данным и результатам тестов;
- загрузка и предпросмотр документов;
- маршруты AI, e-mail и Web Push;
- обработка пользовательского HTML и внешние клиентские зависимости;
- заголовки безопасности Next.js и production source maps;
- зависимости npm, рабочее дерево и Git-история на наличие секретов;
- публичная доступность служебных файлов на `tea-hub.ru`.

Проверка является аудитом кода и базовым усилением защиты. Это не внешний
пентест инфраструктуры, операционной системы, Nginx, MySQL и сети.

## Что исправлено

### Авторизация и сессии

- Production больше не запускается с известным резервным секретом авторизации.
  `AUTH_SECRET` или `NEXTAUTH_SECRET` должен содержать не менее 32 символов.
- Сессия сверяется с текущей учетной записью при каждом обращении. После смены
  роли, логина или пароля старые сессии перестают действовать.
- Подпись cookie проверяется через безопасное сравнение без утечки по времени.
- Новые пароли хешируются через усиленный `scrypt`. Старые совместимые хеши
  автоматически обновляются после успешного входа.
- Хранение и проверка паролей открытым текстом удалены. При успешном входе
  прежнее поле открытого пароля удаляется из учетной записи.
- Production-администратор создается только через защищенные переменные
  `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD`. Тестовые пары доступны
  только в development.
- Для входа, регистрации и смены пароля добавлены ограничения частоты,
  размера тела и длины полей.

### API и разграничение доступа

- Все изменяющие запросы проверяют допустимый `Origin` и тип обращения браузера.
- На чувствительные маршруты добавлены ограничения частоты и размера тела.
- Сотрудник может читать только собственные результаты тестов и историю AI.
- Результат теста вычисляется сервером по сохраненным правильным ответам.
  Переданное клиентом значение балла не используется.
- Попытки и привязка результата к пользователю формируются сервером.
- Сотрудник не может глобально удалить уведомление: сохраняется только его
  персональная отметка о скрытии.
- Запись через общий `/api/storage` ограничена явным списком разрешенных ключей.
  Произвольное имя файла или ключ хранилища больше не принимается.
- Порционная загрузка документов доступна только администратору, ограничена по
  размеру и изолирована идентификатором текущей сессии.
- Создание учебных черновиков через AI доступно только администратору.

### Документы, HTML и внешние библиотеки

- Произвольный HTML больше не вставляется через `dangerouslySetInnerHTML`.
  Видеовставка принимает только URL с протоколом `http` или `https`.
- `iframe` запускается с `sandbox`, ограниченной политикой referrer и без
  доступа к родительскому окну.
- Имена файлов и динамический текст экранируются перед резервным
  `document.write`.
- Внешние скрипты `unpkg` удалены из предпросмотра документов.
- Уязвимый пакет `xlsx` заменен на локальный `read-excel-file`.
  Поддерживаются CSV, XLSX, XLSM и ODS; устаревшие XLS и XLSB отклоняются.
- AI-ключ читается только на сервере. Клиентская переменная
  `NEXT_PUBLIC_AI_API_KEY` больше не поддерживается.
- Тексты e-mail экранируются, SMTP не работает без явной конфигурации.
- Web Push принимает только HTTPS-подписки и ограниченный безопасный payload.

### Заголовки и сборка

- Отключены `X-Powered-By` и production browser source maps.
- Корень output tracing закреплен за папкой проекта, чтобы сборка не захватывала
  посторонние файлы из пользовательского профиля Windows.
- Добавлены CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  строгая referrer policy, COOP, CORP, Permissions Policy и HSTS для production.
- У production-страниц включен `no-store`.
- В production-сборке клиентские `.map`-файлы отсутствуют.
- Прямые запросы к `/.git/config`, `/.env`, `/package.json`,
  `/next.config.ts`, `/app/page.tsx` и `/server.js` на публичном сайте
  возвращают `404`.

## Проверки

- `npx tsc --noEmit` проходит.
- Целевой ESLint для серверных маршрутов и библиотек безопасности проходит.
- Production-сборка проходит через WebAssembly-компилятор Next.js на текущей
  Windows-машине. Нативный SWC-пакет Windows аварийно завершает процесс локально;
  это ограничение локального окружения, а не ошибка приложения.
- `npm audit --omit=dev` сообщает `0` уязвимостей production-зависимостей.
- Полный `npm audit` оставляет предупреждения только в development-цепочке
  ESLint. Автоматическое исправление требует несовместимого обновления ESLint.
- Smoke-проверка production подтвердила заголовки безопасности, `401` без
  сессии и `403` для изменяющего запроса с постороннего Origin.
- Поиск по текущим файлам и Git-истории не обнаружил приватных ключей,
  сертификатов или записанных значений API-ключей.
- Пользовательские JSON в `data/` не изменялись этим аудитом.

## Остаточные риски

### Критический: репозиторий GitHub публичный

Репозиторий `aroslavkorolkov6770-byte/tea-app` сейчас имеет публичную видимость.
Любой человек может скачать полную Git-историю и весь серверный исходный код.
Минификация сайта не решает эту проблему.

Рекомендуемое действие:

1. Подготовить для хоста deploy key или отдельный GitHub token только на чтение.
2. Проверить, что `/var/www/html` сможет выполнять `git pull` из приватного
   репозитория.
3. После этого отдельной командой пользователя изменить видимость репозитория
   на private.
4. Считать ранее опубликованный код уже раскрытым и заменить все секреты,
   которые когда-либо могли храниться вне защищенного окружения.

Видимость не менялась автоматически: это может остановить обновление хоста без
предварительной настройки Git-доступа.

### Высокий: ответы тестов доставляются клиенту

Сотрудник получает структуру теста, в которой присутствует правильный вариант.
Сервер теперь самостоятельно пересчитывает балл, но технически подготовленный
пользователь может посмотреть правильные ответы в данных страницы.

Нужен отдельный серверный API тестовой попытки:

- выдавать вопросы без поля правильного ответа;
- принимать ответы и считать результат только на сервере;
- выдавать итог после завершения попытки.

### Высокий: часть учебного прогресса сохраняется с клиента

Сервер защищает результаты тестов, но часть массивов завершенных тем все еще
приходит из браузера. Для полностью доверенного прогресса нужен отдельный
серверный маршрут завершения темы и серверный расчет всех счетчиков.

### Высокий: обязательная смена старых паролей

После релиза нужно потребовать смену паролей администратора и сотрудников.
Особенно важно заменить ранее использовавшиеся тестовые, короткие и общие
пароли. Секрет авторизации также должен быть новым случайным значением.

### Средний: проверка загружаемых файлов

Размеры и доступ ограничены, но нет проверки сигнатуры файла и антивирусного
сканирования. Перед масштабированием нужны:

- проверка MIME и magic bytes;
- карантин до завершения проверки;
- антивирусный сканер;
- отдельное объектное хранилище без выполнения файлов как кода.

### Средний: rate limit хранится в памяти процесса

Текущий ограничитель подходит для одного процесса, но не синхронизируется между
несколькими PM2-инстансами. При горизонтальном масштабировании нужен общий
лимитер в Redis или на reverse proxy.

### Средний: CSP пока разрешает inline-стили и inline-скрипт

Это требуется текущей теме и архитектуре Next.js. Следующий этап усиления:
перенести стартовый скрипт темы в nonce/hash-схему и постепенно убрать
`unsafe-inline`.

### Низкий: предупреждения development-зависимостей

Они не входят в production runtime. Обновлять ESLint нужно отдельной задачей с
проверкой совместимости конфигурации и устранением старых ошибок линтера.

## Что действительно можно скрыть

- Серверный код, секреты, база данных и пользовательские файлы не должны быть
  публичными и не должны попадать в клиентскую сборку.
- Клиентский JavaScript, HTML, CSS и сетевые запросы всегда доступны человеку,
  который открыл сайт. Их можно минифицировать и не публиковать source maps, но
  нельзя надежно скрыть.
- Реальная защита бизнес-логики строится на серверной проверке прав, серверном
  расчете результатов и приватном репозитории, а не на попытке зашифровать
  браузерный код.

## Обязательные production-настройки

- `APP_ORIGIN=https://tea-hub.ru`
- `AUTH_SECRET` или `NEXTAUTH_SECRET`: новое случайное значение длиной не менее
  32 символов.
- `AI_API_KEY`: только в защищенном окружении сервера.
- `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD`: использовать только при
  пустом хранилище, затем удалить из постоянного окружения.
- SMTP, VAPID, MySQL и SSH-секреты: только в PM2/systemd secret environment или
  другом защищенном хранилище.
- Nginx должен перезаписывать, а не дополнять входящие `X-Real-IP` и
  `X-Forwarded-For`.
- Перед релизом создать архив `data/`, манифест SHA-256 и проверить JSON.
- После релиза проверить вход, смену пароля, роли, документы, тесты, AI и
  журналы ошибок без публикации содержимого секретов.
